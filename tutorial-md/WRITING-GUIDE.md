# 跟练教程 · 写作规范（Worker 执行基准）

> 本文件是所有章节写作者的唯一执行标准。写任何一章前先通读本规范 + 大纲文档。
> 大纲：`docs/ops/2026-08-12-build-along-tutorial-plan.md`

## 1. 输出物与目录

- 目录：`docs/ops/tutorial/`
- 每章一个 Markdown 文件，命名 `NN-slug.md`（NN 为章节序号 00~12，附录 appendix-a/b/c）
- 文件顶部 YAML 风格头注释（用 HTML 注释 `<!-- ... -->` 即可）：
  ```
  <!-- 章节：第X章 · 标题 | 截图：S01~S06 | 状态：草稿 -->
  ```
- 目录索引：`docs/ops/tutorial/README.md`（章节表 + 截图清单总表）

## 2. 语气与受众

- 受众：完全不懂开发的小白 + 未深度用 AI 的 coder。**假设读者一行代码没写过**。
- 语气：像朋友手把手带，口语化、鼓励、不居高临下。多用「你」「我们」。
- 每个概念先类比（生活化），再给真名。类比要克制、一个概念一个类比，不堆砌。
- 不许出现「显然」「很简单」「众所周知」等劝退词。
- 每章目标明确，结尾有「本章你得到了什么」小结。

## 3. 章节统一结构

每章用以下小节骨架（可微调但结构感保持一致）：

```
# 第X章 · 标题
> 本章目标：...

## X.0 先聊两句（引入/衔接上一章）
## X.1 ...
## X.N ...
## 自查清单（Checklist，- [ ] 形式）
## 本章小结（3~5 条要点）
```

## 4. 截图占位符规范（最重要）

正文中所有需要截图处，**必须**使用统一占位符格式，禁止自由发挥：

```
![S01 · Cursor 官网下载页](tutorial-assets/S01.png)
```

- 前缀 `S` + 两位编号，编号与大纲 §3 截图清单严格一致（S01~S43）；
- `alt` 文本 = 「S01 · <截图内容一句话描述>」；
- `src` 统一为 `tutorial-assets/Sxx.png`（官网目录下 `assets/tutorial/`，转换时统一替换）；
- 每张截图引用前用一句话引出，例如：
  > 打开 Cursor 官网，你会看到这样的下载页——`![S01 · Cursor 官网下载页](tutorial-assets/S01.png)`
- **不存在的截图编号不得引用**；一张截图可在多处重复引用（复用场景）。

## 5. 隐私红线（硬约束）

- 禁止出现：真实 AppID / AppSecret / 服务器公网 IP / 真实域名 / GitHub 账号 / 云厂商账号 / 内部密钥 / 服务器系统配置值。
- 一律用占位符：`<你的AppID>`、`<你的域名>`、`<你的公网IP>`、`<你的GitHub用户名>`。
- 教程中的示例域名用 `example.com`，示例 IP 用 `1.2.3.4`，示例 AppID 用 `wx1234567890abcdef`（标注「示例」）。
- 成本表述用区间 + 「以实际为准」。

## 6. 标点与语言硬规则

- 全站禁用 em-dash（—）与 en-dash（–）：一律用逗号/句号/括号或「、」替代。**此规则与官网 verify 门禁一致**。
- 不用 emoji（除非用户明确要求）。
- 中英混排：术语首次出现给英文原名 + 中文含义，如「Taro（一款跨端小程序框架）」。
- 命令与代码用代码块包裹；文件路径用反引号。
- 数字用半角，单位带空格（如 `2C2G`、`<1.5MB`）。

## 7. 事实底座（必须引用真实案例，禁止编造）

- 案例产品：FatTI「找到狡猾的猪腰」= 减脂人格测试 + AI 控卡单微信小程序。
- 真实技术栈：前端 Taro + React + TypeScript + Sass；后端 FastAPI（Python）+ PostgreSQL；部署 Nginx + Cloudflare + 腾讯云轻量服务器；AI 工具 Cursor；LLM 走 DeepSeek/OpenAI 兼容 API。
- 真实迭代节奏：2026-07-20 起步 → 08-12 v1 正式版（约 3 周）。
- 真实 Skills 15 个清单见大纲 §4。
- 成本区间见大纲 §2。
- 技术细节（如 Taro 初始化命令）以大纲/仓库实际为准；不确定的细节写「以你安装的版本为准」，不要编造具体版本号。
- 第 5~9 章必须体现「先纯前端零成本可跑通」的教学承诺。
