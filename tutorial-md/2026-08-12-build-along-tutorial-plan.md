## 0. 目标与受众

**目标**：手把手教用户从 0 构建自己的微信小程序，全程使用 AI 编程工具（Cursor），以 FatTI「找到狡猾的猪腰」为真实案例。

**受众（双人群）**：
- **完全不懂开发的小白**：没写过一行代码，但会用微信、会搜索、愿意跟着步骤点。
- **尚未深度使用 AI 的 coder**：会一些编程，但对「AI 驱动开发工作流」不熟悉。

**教学承诺（案例真实性）**：教程每一步都对应 FatTI 真实踩过的坑与真实解法；项目更新记录完整（ledger + 21 天 journal），是教程素材的先天条件。

**隐私红线（必须遵守）**：
- 不出现真实 AppID、AppSecret、服务器 IP、域名真值、GitHub 账号、云厂商账号；
- 教程一律用占位符：`<你的 AppID>`、`<你的域名>`、`<你的公网 IP>`；
- 成本按市场公开价合理区间表述，标注「以实际为准」；
- 不暴露项目内部密钥/运维细节（如系统 systemd 配置值）。

## 1. 章节大纲（由浅入深）

> 教学节奏：**先扫盲、再准备、后实操**。前 3 章零代码，第 4~5 章开始动手，第 6 章起做功能。
> 每章统一结构：本章目标 → 概念讲解（类比）→ 实操步骤 → 截图占位 → 验证/自查 → 踩坑提醒。

### 序 · 开始之前（为什么要跟这门课）

- 你能做出什么：一个能分享、能上线、能被人扫进微信的减脂人格测试小程序
- 你要准备什么：一台电脑、一个手机、一个能上微信的脑子（不需要会编程）
- 真实案例先导：我们做的 FatTI「找到狡猾的猪腰」，扫一扫体验成品
- **预算表**（见 §2），一句话：**首年千元内可以把小程序跑起来**

### 第 1 章 · 扫盲：先把这些名词混个脸熟（零代码）

**本章目标**：建立地图感，不要求看懂，只要求「见过」。

- 1.1 小程序 vs App vs 网页：分别是什么、为什么选小程序
- 1.2 前端 / 后端 / 服务器 / 数据库：用「餐厅」打比方
  - 前端 = 餐桌和菜单；后端 = 后厨；数据库 = 仓库；服务器 = 餐厅本身
- 1.3 域名 / DNS / HTTPS：门牌号、查号台、带锁的信封
- 1.4 AI 编程是什么：Cursor 这类工具能做什么、不能做什么
- 1.5 Token 是什么：LLM 的「计费字」，为什么便宜到可以忽略
- 1.6 本教程技术栈地图（先混脸熟）：Taro / React / TypeScript / Sass / FastAPI / PostgreSQL / Nginx / Cloudflare

## 5. 官网板块实现方案

### 5.1 板块形态

- 官网导航新增「跟练教程」入口；
- 新建独立长文页面 `tutorial.html`（顶部 sticky 章节目录，锚点跳转，卡片式章节卡）；
- 设计语言完全复用现有 tokens（`--paper/--ink/--accent/--tape/--cream/--sun/--blush`）+ 胶带角标 + mono 编号 + 卡片圆角 + 颗粒条 Signature 点缀；
- 移动端优先单列，桌面端正文窄栏（max-width ~820px）保证长文可读性。

### 5.2 页面结构（tutorial.html）

```
hero（教程标题 + 副题 + 预算速览 + 成品小程序码）
章节目录（sticky，全部章节锚点）
12 章 + 序 + 附录（每章一节，含：目标/概念/实操/截图占位/自查/踩坑）
底部 CTA（返回首页 + 打开小程序）
footer 复用
```

### 5.3 落地文件

| 文件 | 内容 |
|------|------|
| `tutorial.html` | 教程长文页面（新增） |
| `css/tutorial.css` | 教程页样式（新增，复用 main.css tokens） |
| `js/tutorial.js` | 目录高亮 + 截图占位点击替换（新增，轻量） |
| `assets/tutorial/` | 教程用静态图（技术栈关系图、用户截图汇总） |
| `index.html` | 导航加「跟练教程」链接（修改） |
| `scripts/verify.mjs` | 追加教程页断言（章节数/截图占位存在/零 dash） |

### 5.4 风格统一要点

- 颜色/字体/圆角全部来自 `main.css` `:root` tokens，不新增色板；
- 章节卡复用 `.howto__step` 的胶带角标语言；
- mono 编号（01/02/…）对齐官网 `feature__kicker` / `howto__num` 视觉；
- 截图占位统一为「白卡 + 虚线框 + mono 文件名」风格，用户替换后视觉一致；
- 全站零 em/en-dash（verify 硬门禁）已内建。
